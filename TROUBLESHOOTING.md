# Troubleshooting — Local Voice Studio

## Установка

**"Python не найден" при запуске install.bat**  
Установите Python 3.11 или 3.12 с python.org, отметьте "Add to PATH" при установке.

**Ошибка при установке PyTorch / CUDA**  
install.bat пытается поставить сборку с CUDA 12.4. Если у вас другая версия драйвера
NVIDIA, проверьте `nvidia-smi` — драйвер должен поддерживать CUDA >= 12.4 (актуальные
драйверы 2025-2026 годов поддерживают). Если install.bat автоматически откатился на
CPU-версию — TTS будет работать, но крайне медленно (RTF намного больше 10).

**FFmpeg не найден**  
Это не критично: используется резервный движок из пакета `imageio-ffmpeg` (ставится
автоматически через requirements.txt). При желании поставьте системный FFmpeg и
добавьте его в PATH — тогда будет использован он.

## Запуск

**Приложение не запускается / падает сразу**  
Смотрите `logs/app.log` — там подробный traceback. Частые причины:
- venv не создан или повреждён → удалите `.venv` и запустите `install.bat` заново.
- CUDA недоступна → см. раздел ниже.

**"CUDA недоступна" в статус-баре**
1. Проверьте `nvidia-smi` в PowerShell — если команда не найдена, драйвер NVIDIA не установлен.
2. Проверьте, что PyTorch установлен с поддержкой CUDA: `.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"`.
3. Если `False` — переустановите PyTorch: `.venv\Scripts\python.exe -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu124 --force-reinstall`.

## Генерация речи (MODE 1)

**CUDA Out of Memory**
- Переключите Preset на `fast` (использует модель 0.6B, VRAM ~2.7 GB вместо ~4.6 GB).
- Закройте другие приложения, использующие GPU (проверьте `nvidia-smi`).
- Уменьшите длину текста за один вызов — очень длинные тексты требуют больше памяти
  на attention-матрицы.

**Генерация очень медленная (RTF > 3-4)**  
Это известное ограничение Qwen3-TTS без FlashAttention 2 на потребительских GPU
(см. `docs/MODEL_RESEARCH.md`, раздел «Риски», и `docs/BENCHMARK.md`). FlashAttention 2
на Windows ставится сложно (нужна компиляция с MSVC + конкретная версия CUDA toolkit).
Если хотите попробовать: `pip install flash-attn --no-build-isolation` внутри `.venv`
— если сборка не удаётся, оставайтесь на текущем sdpa-режиме, он корректен, просто медленнее.

**Голос совсем не похож на референс**
- Проверьте `Reference quality` в панели профиля — если BAD/ACCEPTABLE, добавьте более
  качественный референс (10-30 сек чистой речи без музыки/шума/множества голосов).
- Убедитесь, что `ref_text` (транскрипт референса) точно соответствует произносимым
  словам — несовпадение текста и аудио сильно портит клонирование (модель "путается",
  иногда обрезает или искажает результат). При автозагрузке транскрипт строится
  автоматически через faster-whisper — если распознавание ошиблось, отредактируйте
  референс (удалите и загрузите заново более чистую запись).
- Нажмите "Пересоздать профиль" после замены референсов — кэш voice-prompt иначе не
  обновится.

**Пустой/тихий WAV на выходе**  
Проверьте `logs/app.log` — если генерация завершилась без исключения, но звук пустой,
скорее всего проблема в `ref_text`/`ref_audio` рассинхронизации (см. выше) либо в
слишком короткой/тихой референсной записи.

## Voice Conversion (MODE 2)

**"Seed-VC не установлен"**  
MODE 2 требует отдельного окружения `models/seed-vc/.venv-vc` — см. `INSTALL.md`,
раздел "Voice Conversion setup". Оно не создаётся автоматически `install.bat` (это
тяжёлая отдельная установка, ~2.5 GB PyTorch + модель), запустите его один раз вручную.

**Voice Conversion работает, но результат звучит роботизированно/с артефактами**  
Увеличьте `--diffusion-steps` (в config.json: `quality_presets.<preset>.vc_diffusion_steps`)
— больше шагов диффузии = выше качество, но медленнее.

## Микрофон (запись референса / MODE 3)

**Список устройств пуст**  
`sounddevice` не увидел микрофон — проверьте, что микрофон включён в Windows
(Параметры → Конфиденциальность → Микрофон → разрешить приложениям рабочего стола).

## API

**API не отвечает на 127.0.0.1:8722**  
Проверьте, что `api_enabled: true` в `config/config.json`, и что порт не занят другим
процессом (`netstat -ano | findstr 8722`).

## Логи

Все проблемы в первую очередь диагностируются через:
- `logs/app.log` — общий лог приложения.
- `logs/benchmark.jsonl` — история производительности генераций.
